# Methodology

报表资产解析与治理的目标，是把历史 BI 报表转换为可检索、可追溯、可被 AI 使用的结构化资产。

## 为什么先做报表资产盘点

制造业企业的业务问题通常已经在历史报表里被分析过很多次，例如订单交付、采购执行、产能、良率、库存、物流和经营分析。

AI 问数失败时，常见原因不是模型不会写答案，而是模型不知道：

- 哪些报表与问题相关；
- 报表背后的 SQL 是什么；
- 口径用了哪些参数；
- 数据来自哪些表和字段；
- 字段或表结构变动会影响哪些报表。

因此，AI 需要的不是更长的提示词，而是一份可检索的企业报表资产上下文。

## 解析对象

Demo 中展示的解析对象包括：

- 报表资产；
- 数据集；
- SQL 片段；
- 参数；
- 源表 / 视图；
- 输出字段；
- 文件路径与目录线索；
- 表字段引用关系；
- MCP 查询上下文。

## 基本链路

```text
报表文件 / BI 平台目录
  -> 受控扫描
  -> 结构解析
  -> 资产摘要
  -> Spec JSON
  -> 引用反查
  -> MCP / Agent 查询
```

## AI 使用方式

AI 不直接回答“毛利率为什么下降”或“生产进度为什么停住”，而是先做几步：

1. 搜索相关报表和资产；
2. 读取资产摘要；
3. 查看数据集、SQL、参数和字段；
4. 定位口径来源；
5. 反查相关报表影响范围；
6. 基于证据组织回答。

这种方式不能彻底消灭幻觉，但能显著减少没有依据的回答。
